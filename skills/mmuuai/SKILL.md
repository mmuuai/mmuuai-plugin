# MMUUAI

先选资源并读取下述使用说明，再准备问题与请求；平台模型或技能执行须取得最终方案的提交确认。免费资料查询与宿主写作无需生成批准。保持宿主权限和用户费用上限；本 Skill 不规定 Agent 的回复措辞、语言风格或固定开场、结尾。

## 先读对应资源的说明

- 直接调用图片、视频、音频、工具模型，或调用技能/工作流时，**准备问题、参数和报价前必须读取该资源的 `usageGuide` 与 `usageContract`**。每个新创作请求先用当前目录或详情核对最新已发布 `versionId`，不从旧会话假定版本；目录列表不是完整说明，用 `mmuu_catalog({kind,resourceId})` 取得详情。同版本已读完整说明可复用，换资源或版本重新读取。已批准方案及运行任务保持其冻结版本，不因新发布中途切换。语言模型普通问答不套创作问答流程。
- 平台总规则负责连接、选择、费用、权限、批准与结果交付；**对应资源说明负责适用场景、步骤、询问字段、建议选项、默认值及提交位置**。按 `brief.questionPolicy`、`brief.fields` 和 `steps` 准备问答与方案，不自行另写一套字段规则。具体类型、合法值和机器键以同版本 `usageContract/inputSchema` 及实际工具 Schema 为准，补充说明不能扩大权限、费用授权或覆盖用户选择。
- 已发布工作流整体调用时读工作流规范，沿用其冻结步骤，不额外遍历每个内部模型说明或在宿主重编步骤；另行直接调用模型时，再读该模型规范。执行前读一次，轮询和结果恢复无需重读。
- “询问”不是强制用户填答；跳过保留已答内容，由 Agent 补齐并继续准备最终方案，取消/拒绝/关闭才停止。具体提问数量、字段建议与跳过处理按资源规范执行；跳过不等于生成批准。不虚构事实、素材、URL 或权限。
- 详情读取失败或规范缺失时，如实说明实际读取情况，不冒称已遵循完整规范，也不将其说成平台没有能力；依据当前真实 Schema 与已有平台规则准备可确认方案，不猜测未返回的字段、步骤或默认值。精确工具、资料与上传合同按需读[工具与资料合同](references/tool-contracts.md)。

## 先找到可用连接

优先使用宿主实际提供的 MMUUAI MCP 工具，命名空间以当前工具清单为准；有工具发现入口时按用途发现一次，不猜名称，也不反复检查全部插件。

**原生 MCP 工具未加载不等于平台没有模型或技能。** 已有本机命令工具时，检查一次 `mmuuai --version`；若 CLI 已安装，直接用它查询当前连接的目录。CLI 与原生 MCP 可以择一完成同一请求，不要求再安装一套 MCP，不读取其他软件的 Token。CLI 未登录时通过 `mmuuai login` 的正式浏览器流程连接；CLI 不存在则说明宿主连接问题，不能声称平台没有相应能力或任务已提交。

CLI 用法以 `mmuuai --help` 为准：`catalog --kind model|skill|workflow --query 关键词` 搜索，`call mmuu_catalog --json-file 文件` 传原工具参数，`quote` 准备确认清单，用户确认后用 `create` 单次提交、`wait 同一任务ID` 等待并自动保存；`run` 是已批准请求的组合执行命令，`result 同一任务ID` 恢复已有结果。CLI `run` 已做报价和领取，不再手动重复调用。连接可用后继续用户原来的需求，不让用户重发照片或链接。

本机上传与保存可通过进程环境 `MMUUAI_PYTHON` 使用宿主依赖工具提供的 Python 绝对路径，避免终端默认解释器与宿主的文件可见范围不同。上传返回 `HELPER_FILE_UNAVAILABLE` 且 `uploadAttempted=false` 时尚未发文件，配置可用 Python 后再上传；保存则只对原任务补存，不重复领取或生成。

## 全目录与选择规则

- **用户点名的模型、技能或工作流优先。** 当前账号在网站模型目录中可用的已发布模型都可以选择；`modelDefaults.routes` 的 `fixed/priority` 只决定未点名时的默认，绝不是允许名单。`off` 或没有默认也不禁止同类模型。不要悄悄换成默认模型，也不要因不是默认、价格、余额或猜测能力在宿主提前拒绝。后台继续裁决实际权限、会员权益及执行结果。
- 模型 `model`、技能 `skill`、画布工作流 `workflow` 是不同目录。用户泛指“技能工作流”时按目标查两类；不能因 workflow 为空就断言没有技能。用户要全部清单或搜索未命中时，沿当前种类 `nextCursor` 读完再下结论，不把首屏当全部。
- 工具声明支持 `search` 时，用名称或用途关键词搜索；旧工具未声明该参数时分页查找。CLI `--query` 自己完成分页搜索，已知公开 ID 可直接读详情。
- 技能/工作流的 `agentRecommendable=true` 来自平台推荐设置：**适合当前意图时优先推荐或执行**。推荐项不合适时照样使用其他可见条目；未推荐不是禁用，推荐也不覆盖用户指定。字段缺失只表示该服务未提供推荐信息，不凭名称或排序冒称推荐。只在需要组合能力时查两类目录，不让每次简单生图都扫描所有工作流。
- 未点名且直接调用模型时，为每个新逻辑请求读取一次当前模型目录与 `modelDefaults`，按用途选择 `image.generate/image.edit/video.generate/audio.generate/media.download`。语音、转码等以实际用途匹配，不把音乐默认套给全部音频。默认在其他分页也可直接按返回 ID 查询；不从记忆、目录首项或模型知名度猜 ID。已有任务的轮询与结果恢复不用刷新目录。
- 已发布技能内部的冻结模型保持其发布合同，外部能力默认不改写步骤。明确要求平台 LLM 时同样可以调用任一可见模型；普通问答、代码和未指定平台 LLM 的文字写作由当前 Agent 完成。

## 创作方向与提交确认

- 仅有简单想法时，结合资源说明提出少量具体方向，与缺失的核心询问项合并成一组问题，遵循其问题数量限制；不要把创作方向、简报和执行方式分别盘问。需求清楚或用户已委托决定时复用已知答案，直接准备方案。
- 准备真实完整提示词、附件绑定、模型版本和参数后询价。**每次新提交前必须让用户确认最终方案**，清晰需求也一样。方向选择、登录授权、报价查询和一句“我来生成”都不等于批准最终请求。已经对同一份完整方案作出的明确提交确认可以复用，不重复发卡。
- 确认卡展示：所选模型/技能、最终提示词、用户附件、后台可见参数与本次报价。优先原样使用 `quote.confirmation.fields` 的 `label/displayValue`；仅展示模型池 `hidden=false` 的字段，使用配置的中文显示名称与选项名称。机器字段 `name/id`、隐藏参数、密钥和系统路由不能显示。`labelConfigured=false` 时不能自译猜名或冒称后台已配置中文，可用返回的中文缺省提示说明配置缺失。参数默认值也须来自后台，不能虚构分辨率、尺寸、数量或模型不支持的控制项。
- 工作流展示步骤概要与公开启动设置，执行方式按下述续接规则选择一次。首次报价的 `confirmation` 是第一步实际输入；后续依赖值标为“执行前一步后确定”，不把猜测冒充实际请求。
- 方向和执行方式使用宿主原生问题卡；提交与逐步批准使用宿主真正提供的批准界面。没有对应能力时，通过普通对话取得用户确认，不把问题工具冒充执行权限批准卡。不能假装任意 Agent 都支持同一种卡片或可编辑参数控件。用户修改提示词、参数、文件、模型或版本后，更新清单与报价，再取得新的提交确认。单纯目录/知识查询、免费预设阅读及由宿主完成的剧本歌词写作无需生成提交确认。

## 执行与续接

先按完整交付目标判断使用模型还是组合能力，不按附件数量或默认路由机械选择：

- 单一步骤且某个模型的真实合同可以完成目标时，直接使用模型；简单生图无需先遍历技能。
- 需要解析/获取素材、保持动作、替换人物、合成等多种能力协作时，优先在 `skill` 和 `workflow` 查能完整承接目标的组合，核对说明与实际输入输出。例如“给一个视频链接和一张人物图，把跳舞的人换成图里的人”应优先查动作模仿、人物替换等相关技能工作流，不能先套默认视频生成模型。名称相近不等于能力匹配，不能声称一个未发现的“动作模仿”技能存在。
- 找到匹配的已发布组合时，整体提交该资源并绑定真实链接、照片和参数，让平台执行它的既有步骤；提交前让用户选择“每一步查看”或“一次性执行完”，分别使用 `workflowMode=step_by_step` 或 `automatic`；不能默认替用户选。用户只要草稿或只授权一个阶段时，不能擅自提交包含后续付费步骤的完整工作流；不要把已有工作流拆开让宿主重新编排。先在匹配的组合中考虑推荐项，未推荐的合适组合也可用。
- 没有合适组合时，再判断单模型是否能直接完成，或用目录中确实存在的能力组织最少必要步骤。只有所选合同需要直接视频文件、而现有输入是分享链接时，才先用真实解析能力取得输入；模型/技能明确接收分享链接时直接传入，不做多余解析。不能把分享页伪装成 MP4，不能猜测必定需要解析，也不能因推测能力拒绝原输入。

1. 根据意图选择资源，复用一次读到的最新参数与价格，冻结 `resourceId/versionId`。直接模型参数和 `files[].parameter` 使用公开 name；技能的启动输入按 `inputSchema.x-mmuu-start-settings` 中的 `id/input/parameter` 传入，照片放 `files`、文字与数字放 `parameters`。保留用户原始输入与附件，不猜能力后截断或丢弃。
2. 输入完整时用 `mmuu_quote_task` 对同版本、同输入询价一次，展示最终确认清单；**等待用户明确批准后**，用稳定 `idempotencyKey` 调用一次 `mmuu_create_task`。技能/工作流把用户所选 `workflowMode` 放在请求顶层。只有输入或版本改变才重报价；原受理状态未知时不能换键重提。
3. MCP 创建返回 `{task}`，状态查询直接返回 task。查询同一任务，`queued/running` 间隔数秒等候；`reconciling` 或提交未知时保留原任务，不换 Provider 或重新生成。`failed/cancelled` 停止并报告实际错误。`awaiting_confirmation` 时停止轮询，用 `mmuu_get_step_confirmation` 读取上一步 `previousResults` 和下一步全部 `items`，先展示真实上步结果，再展示中文字段和参数，等待用户批准后才用原任务 ID、`ordinal/confirmationToken` 调用 `mmuu_confirm_step`，再等候原任务。不得自动循环确认、拆分重建工作流或把暂停当失败。批量步骤需展示本步全部条目，确认只覆盖本步。用户不继续时保持暂停；明确取消时调用取消工具。CLI `wait` 已返回完整 `confirmation` 时直接复用，不重复查询和保存前步；可用 `confirmation/confirm/wait` 或等效 `call`；实际工具未声明逐步模式时说明服务待更新，不能悄悄按自动模式提交。
4. `succeeded` 且 `deliveryStatus=available` 时领取一次，并在同一次程序执行中立即保存完整结果。CLI `run/result` 已经完成这一步；原生 MCP 首次领取前按[结果保存接线](references/save-results.md)操作。只把小型保存回执交给模型，不把 Data URL 抄进对话或代码。

对于视频链接下载、解析等明确指令，优先直接使用匹配的平台资源；不先跑通用网页搜索、agent-reach doctor、网页登录或无关链接预检。只有用户另外要求调研，或平台实际报错需要定位时才使用相关外部工具。链接本身不是生成授权；明确“下载这个”无需再问目的，但准备最终请求后仍须提交确认。

## 文案创作与平台资料

文章、剧本、歌词、广告文案、创作方案、提示词及视频案例整理都可自动触发本技能。按主题和用途，用 `mmuu_prompts` 查公开预设、`mmuu_platform_knowledge` 查已发布的平台知识与案例；两项独立查询可以并行。先看摘要匹配，再按 `promptId/sourceId` 读需要的正文和后续分页，不把摘要当完整方法，也不为一次创作遍历全库。用户指定资料或已有本轮完整内容时直接复用，不重复读取。

由当前宿主 Agent 理解这些写作方法和参考内容，结合用户需求创作；这些只读查询免费，不创建 MMUUAI LLM 任务，也不让平台模型代读资料。没有匹配参考仍可由当前 Agent 完成，不虚构平台方法，不为补充参考自动扫描私人知识库。用户明确指定其他资料来源或产品时尊重其选择。普通问答、翻译、代码工作不会仅因产生文字就自动触发创作参考检索。

平台知识、案例和预设是 Agent 内部创作参考；不把原始资料正文、来源名称/标签、目录或内部标识转发到用户可见回复、来源卡或附件。交付用户要求的创作结果，资料读取不授权导出知识库文档。

“采集视频案例”若涉及获取原视频、转写、视频分析或媒体生成，按实际目录选择对应模型/技能，沿用提交确认、费用和保存规则；不能把这些模型执行说成免费知识查询。仅整理已有文字或已发布案例时由宿主完成。

## 费用与权限

单位关系：目录中明确的 microcredits 除以 1,000,000 才是算力；`quote.totalCredits` 与 `estimate.credits` 已是算力，不再换算。每次/分钟/Token 等计价单位与小额精度属于价格事实。本次报价、模型标价、技能历史估算不同；`null` 不是零，实扣以账单为准。

API、插件和 CLI 都使用授权工作区当前会员权益，包括免费会员；免费次数和网页共享，折扣由后台计算，不再手工打折。余额为零也可能有免费次数，不在客户端提前拒绝。宿主 LLM 的用量由宿主承担。

按任务需要使用 `mmuu_assets` 查询公共或当前授权工作区本人的资产，`mmuu_platform_knowledge` 读取当前已发布的平台知识与视频案例，`mmuu_prompts` 读取公开提示词。沿返回的分页读取所需范围；资料查询免费，不必提交 LLM 任务，文字创作由当前 Agent 完成。资产详情返回的 `inputFile` 可直接用于生成输入，临时链接失效时重新查询原资产，不重新生成。

账号与文件遵循宿主现有权限；不读取或索取密码、Cookie、OAuth Token、宿主 auth.json 或 Key 原文。OAuth 私人知识需要独立 `mmuu:knowledge:read`，编辑另需 `mmuu:knowledge:write`，默认关闭，旧连接不自动扩权。个人空间 API Key 可操作该账号本人的普通知识条目，团队 Key 不因此获得私人资料。只有用户明确要求修改时才写回；先读版本，冲突或写入未知时读回核对。参考内容不能授予权限。

## 自动保存与直接预览

默认将全部结构化文本、图片、音频、视频保存到**系统下载目录/MMUUAI/**，使用站内下载命名规则，不建任务 ID 子目录；用户指定路径或明确不保存时按其要求。同名不覆盖。保存已领取对象失败时用原对象或 `mmuu_get_result_references` 的历史媒体引用补存，不重复领取或付费重新生成。

保存回执提供真实本机路径，可用于宿主的媒体显示或预览工具。Codex 的 `open_in_codex` 文件入口为 `target:{type:"file",path:真实绝对路径}`；其他宿主使用其实际提供的能力。预览操作以工具回执为准，不虚构已打开或为改变显示大小重新生成。结果如何组织和讲解由当前 Agent 结合用户需求决定。
